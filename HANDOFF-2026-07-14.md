- **`CLAUDE.md` is Claude Code's own memory file, continuously updated by
  Claude Code sessions.** It is NOT this session's memory — I (this
  claude.ai conversation) have no access to Claude Code's session history
  at all, confirmed via `conversation_search` returning nothing relevant.
  Everything in this handoff was learned by reading files fresh, same as
  any new session would.
- **The actual "colossal fail":** Quill, in Claude Code, hit a 57-turn
  agentic loop and 2.9M tokens on article #20 — separately, Cowork
  suggested porting the workflow to Claude Code using Opus, and per Joe,
  Opus ignored explicit prompts during that work. Current `CC_MODEL_OVERRIDE`
  has every agent set to `None` (Sonnet default) — nothing is pinned to
  Opus right now.
- **`single_shot=True` (in `agents/base.py::call_cc_agent`) is the real
  fix for agentic-loop token blowouts** — one turn, no tools, everything
  inlined. Cora and Vera both use it and both are confirmed cheap/reliable.
  Quill's old `max_turns=3` (before today's full rewrite) was a partial,
  interim measure — worth knowing if this pattern needs applying elsewhere.
- **Desktop Commander's live process-output tooling hiccupped 3 times this
  session** (`start_search`, `list_processes`, `move_file` all returned
  "no result" once each). None were fatal — falling back to reading
  `pipeline.log` / `last-run-status.json` directly off disk worked every
  time and is more reliable than trusting streamed subprocess output
  anyway. If a fresh session hits the same thing, that's the move.
- **`git commit` (no `-a` flag) only commits staged files** — this is why
  publishing #25 didn't accidentally commit any of today's code changes;
  Maya's own `git add` only stages the article + images it just built.
  Worth remembering before assuming a commit will sweep in more than intended.
